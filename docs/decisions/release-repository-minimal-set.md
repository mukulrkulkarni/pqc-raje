# Release Repository Minimal Set

**Status:** Proposal only. Does not change the released v0.1 tree.

## User release contents

- `README.md`, `LICENSE`, `CHANGELOG.md`, and Getting Started.
- Launcher and runtime `app/` and `electre3/` code.
- Required local assets/templates.
- User CLI/web guides, debugging guide, examples, and built website if distributed.
- Explicit dependency/version manifest.

## Development-only contents

- `tests/`, benchmarks, preflight tooling, build scripts, and CI files.
- Detailed decision records, review reports, checkpoints, scratch output, and audit logs.

## Archive contents

- Historical snapshots, raw attachments, screenshots, mockups, old generated pages, and preserved evidence.
- Keep archive provenance manifests. Do not delete evidence to make a release tree small.

## Generated website policy

Authoritative tutorial HTML and assets live under `docs/modules/`. Website tutorial copies are generated by `scripts/build_website.py` and must not be hand-edited. Website-owned landing pages require explicit source ownership. A future packaging chunk must define an allow-list and deterministic clean-output build.

## Acceptance

A clean release package must contain only the user-release allow-list, pass launch and link checks, preserve local assets, and exclude tests, checkpoints, archives, and internal decisions. Packaging is future work and needs separate approval.
