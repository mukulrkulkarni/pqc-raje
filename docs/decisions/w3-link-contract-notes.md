# W3 Link Contract Hardening

## Scope

W3 protects local links without changing Flask workflow logic, content, release tags, or no-JavaScript boundaries.
The canonical contract is [link-contract.json](../link-contract.json).

## Namespaces

- **Static site:** `website/` serves directory URLs with trailing slashes and explicit static files.
- **Flask:** documentation routes use exact no-trailing-slash forms, except `/` and `/app/`.
- **Examples:** static pages use `/examples/index.html`; Flask renders the configured companion origin plus that fixed path.
- **Generated output:** `scripts/build_website.py` owns copied tutorials, tutorial assets, and `website/examples/assets_priority/`.

## Positive evidence

`tests/test_w3_link_contract.py` parses each website HTML file. It resolves local `href`, `src`, `action`, and `poster` values from the source page, checks target files and HTML fragments, and classifies HTTP(S) and mail links without fetching them.
It verifies Flask canonical documentation routes, nested tutorial assets, static Examples, generated tutorial coverage, and stale-output deletion.

## Negative and edge evidence

The W3 checks deliberately prove resolver errors for a missing file, missing fragment, and path escaping the website root.
They reject Flask traversal, double-encoded traversal, backslash traversal, unsupported trailing slashes, protocol-relative targets, and companion URLs with credentials, paths, fragments, or redirect-like forms.
External links remain classified only; W3 performs no remote request.

## Commands and results

Run from the repository root:

```text
python -m pytest tests/test_w3_link_contract.py -q
python scripts/build_website.py
python -m compileall -q app electre3 scripts
python -m pytest -q
```

## Tutorial notes

Source tutorials remain in `docs/modules/*_tutorial_side_by_side.html`.
The static derivatives remain generated by `scripts/build_website.py`; do not manually repair a generated tutorial.
Tutorial fragment links resolve within their rendered HTML. No browser checks run in W3; browser, assistive technology, zoom, reflow, keyboard, offline, and load evidence remain deferred and non-blocking.

## Review evidence

- **Engineering:** focused resolver checks and the full suite passed; generated ownership remains in the existing builder.
- **Security:** traversal, encoded-path, backslash, protocol-relative, and companion-origin rejection checks passed.
- **UIUX:** static navigation, Examples destination, fragments, and no-JavaScript boundaries remain covered by focused UI checks.
- **Scientific:** not required; W3 changes no ranking content, inputs, formulas, or results.
- **Independent reproducibility:** local build, compilation, focused test rerun, and full-suite commands above succeeded.

## Limitations

The resolver does not execute JavaScript, fetch external URLs, validate live deployment routing, or emulate browser URL normalization beyond its tested local safety rules.
