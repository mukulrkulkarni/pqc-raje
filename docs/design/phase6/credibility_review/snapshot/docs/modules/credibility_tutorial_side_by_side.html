Notation — read this first

a and b are objects Both are alternatives: things being ranked (IP addresses, items, projects). They are not criteria. A criterion is a property we measure on every object.
a → b is an assertion under assessment a → b reads “a is at least as good as b”. We are testing this claim, not stating it is already established. b → a is a different claim with its own numbers.
Counts (no symbol collisions)
  • N — number of objects in the whole dataset
  • C — number of criteria (a count only)
  • C(a,b) — global concordance of the pair; in [0,1] under the weight contract below; never plain C
B1 and B2 count objects in comparison groups One block compares a group of B1 row objects (playing a) against a group of B2 column objects (playing b). Both groups contain object rows from the same performance matrix, not groups of data fields. Row/column names describe their positions in the pairwise result. Groups may overlap, and B1 need not equal B2.
Why diff has three axes (B1, B2, C) diff[i,j,k] = g(row i, crit k) − g(col j, crit k). Here g(a,j) is the oriented performance of object a on criterion j. Axis 1 picks the row object, axis 2 the column object, axis 3 the criterion. Every a,b pair gets one number per criterion.
Triple brackets [[[d1, d2, d3]]] = B1 = 1 (outer), B2 = 1 (middle), C = 3 (inner). Two objects {A, B} give two non-self directed comparisons: A→B uses g(A)−g(B), B→A uses g(B)−g(A); same magnitudes, flipped signs.

I/O Summary

credibility(C_ab, d_j) Inputs: floating-point C_ab: ndarray(B1,B2), d_j: ndarray(B1,B2,C); finite values in [0,1], matching object axes, at least one criterion.
Output: new S: ndarray(B1,B2); input arrays remain unchanged. Preconditions are not validated here.
C counts criteria; C(a,b) denotes the concordance value held in C_ab. They are not interchangeable.

Scientific grounding, interpretation and sanity checks

Definition: Credibility measures support for the directed assertion that object a is at least as good as object b after objections are considered. It is not a probability, distance or total order. Opposite directions may both have support; pairwise relations can be non-transitive.

Calibration: This function has no new tuning parameter. Weight and threshold choices affect its upstream inputs. Vary those choices in a controlled sensitivity analysis rather than interpreting a score as an objective probability.

Boundary convention: This implementation explicitly overrides the reduction product with a full-veto rule. A call with C=1 and d=1 returns zero, not one. Such inputs may be inconsistent with an ordinary upstream dataset; the low-level contract nevertheless defines them. Do not infer this boundary from a formula that omits the override.

Sanity checks: Verify finite [0,1] inputs and matching axes. Under those conditions, factors cannot exceed one, so S cannot exceed C. Check no-reduction, partial reduction and full-veto cases independently. This implementation clips output to [0,1], but clipping does not validate inputs or detect missing criteria.

Validation ownership: Constructor and ranking-entry checks protect normal pipeline inputs. Direct callers must check arrays themselves. NaN in discordance can fail both masks and silently leave a finite S, so a bounded result does not prove clean inputs. Diagonal exclusion is downstream; this function does not enforce S(a,a)=0.

Purpose

Credibility combines global support with individual objections for each ordered object pair. It produces an outranking credibility score, not a sorted list or an ELECTRE III distillation result.

I/O

The module exports credibility(C_ab, d_j). C_ab has two object axes; d_j adds a criterion axis. The result retains only the two object axes because criterion effects have been combined.

Why

Keeping support and opposition separate prevents a strong objection from being averaged away. The upstream weights affect C_ab, but no weight vector is passed here and full veto is not weighted.

Pitfalls

Do not label S a probability or assume symmetry or transitivity. This repository uses net-flow exploitation after credibility; that ranking choice is distinct from the pairwise credibility construction.

27    S = C_ab.copy()

Purpose

Start with S=C_ab.copy(), preserving the input concordance. The copy becomes the running result while each criterion slice supplies one objection value per object pair.

I/O

Use floating-point arrays with C_ab shape (B1,B2) and d_j shape (B1,B2,C). The object axes must agree and C must be positive. Both inputs must be finite and in [0,1]; no internal checks enforce this contract.

Why

Copying prevents repeated calls from changing the upstream concordance. It also lets the mask compare each objection with the original C_ab rather than with an already reduced running score.

Pitfalls

Integer C_ab preserves integer dtype in its copy and can fail during in-place floating multiplication. Empty criteria silently skip the loop. Mismatched dimensions may error or broadcast unexpectedly. A clipped result cannot reveal these input mistakes.

30    n_criteria = d_j.shape[2]
31    for j in range(n_criteria):
32        d = d_j[:, :, j]
34        # Full veto (d=1) always sets S=0
35        S[d >= 1.0] = 0.0

Purpose

For the current criterion, set selected entries of S to zero where d≥1. For valid inputs that means d=1, the full-veto boundary. This rule also applies when C_ab equals one.

I/O

The Boolean mask indexes the running output copy only. C_ab and d_j are unchanged. Each loop iteration applies to all B1×B2 pairs at once.

Why

A full veto is not a small reduction factor. Once S becomes zero, later multiplication by valid factors cannot restore support. A low-weight criterion can veto because weights are not part of this condition.

Pitfalls

Do not say d=1 merely “may reduce” credibility in this implementation. Conversely, an interior d does not necessarily reduce S: it must exceed C_ab. Test veto before and after another criterion to catch accidental restoration.

Purpose

For each criterion satisfying C_ab<d<1, multiply S by (1−d)/(1−C_ab). Criteria at or below C_ab contribute factor one and need no update.

I/O

mask is a Boolean matrix matching the object axes. Boolean indexing selects matching entries of d, C_ab and S. Multiple qualifying criteria multiply successive factors; all denominators use the original concordance.

Why

For valid selected entries, 0≤C_ab<d<1 implies a positive denominator and a factor between zero and one. Therefore the product cannot increase C_ab. The shared example gives C=0.7, d=5/6 and S=7/18.

Pitfalls

Comparing each d to the running S instead of C_ab would change the model. At d=C_ab the strict comparison excludes reduction. Criterion permutations are mathematically equivalent, but floating-point multiplication order can introduce small differences.

Purpose

The denominator guard and final clipping are defensive numerical operations, not input validators. For valid selected entries the denominator is already strictly positive because C_ab<d<1.

I/O

At C_ab=1, no valid interior d satisfies the reduction mask. All d<1 leave S=1; any d=1 invokes the separate veto and gives zero. At C_ab=0, valid factors cannot increase the initial zero.

Why

The 1e-10 substitution is not a tunable tolerance and is not needed to decide the valid C=1 boundary. Near one, subtraction can lose relative precision. Check boundaries with suitable numerical tolerances, not invented performance guarantees.

Pitfalls

NaN discordance can be silently ignored by comparisons; NaN concordance can remain NaN. Out-of-range inputs invalidate S≤C even if clipping returns [0,1]. No diagonal is cleared here. Work scales as O(B1×B2×C); scratch/output storage is O(B1×B2), excluding the input discordance tensor.

Run the credibility example

Illustrative inputs only. Do not treat these thresholds as recommended defaults. This code computes the table above, rather than printing a prewritten result.

Python — same A, B and three scenarios as above
import numpy as np
from electre3.concordance import (
    partial_concordance, global_concordance,
)
from electre3.discordance import discordance
from electre3.credibility import credibility

A = np.array([10., 5., 7.])
B = np.array([8., 7., 6.])
q = np.array([1., 1., 1.])
p = np.array([3., 3., 3.])
v = np.array([6., 6., 6.])
weights = np.array([0.5, 0.3, 0.2])
results = []
for second_value in (7., 10.5, 11.):
    scenario_B = B.copy()
    scenario_B[1] = second_value
    diff = (A - scenario_B)[None, None, :]
    c = partial_concordance(diff, q, p)
    C_ab = global_concordance(c, weights)
    d = discordance(diff, p, v)
    S = credibility(C_ab, d)
    results.append((second_value, d.copy(), C_ab, S))
    print(second_value, d, C_ab, S)

Interpretation

Each scenario still compares two objects. Only B's second measured performance changes. The criterion count and all thresholds and weights remain fixed.

For the reverse direction, swap A and scenario_B when forming diff. Do not negate the returned discordance scores.
