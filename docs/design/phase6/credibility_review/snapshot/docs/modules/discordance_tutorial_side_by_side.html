Notation — read this first

a and b are objects Both are alternatives: things being ranked (IP addresses, items, projects). They are not criteria. A criterion is a property we measure on every object.
a → b is an assertion under assessment a → b reads “a is at least as good as b”. We are testing this claim, not stating it is already established. b → a is a different claim with its own numbers.
Counts (no symbol collisions)
  • N — number of objects in the whole dataset
  • C — number of criteria (a count only)
  • C(a,b) — global concordance of the pair; in [0,1] under the weight contract below; never plain C
B1 and B2 count objects in comparison groups One block compares a group of B1 row objects (playing a) against a group of B2 column objects (playing b). Both groups contain object rows from the same performance matrix, not groups of data fields. Row/column names describe their positions in the pairwise result. Groups may overlap, and B1 need not equal B2.
Why diff has three axes (B1, B2, C) diff[i,j,k] = g(row i, crit k) − g(col j, crit k). Here g(a,j) is the oriented performance of object a on criterion j. Axis 1 picks the row object, axis 2 the column object, axis 3 the criterion. Every a,b pair gets one number per criterion.
Triple brackets [[[d1, d2, d3]]] = B1 = 1 (outer), B2 = 1 (middle), C = 3 (inner). Two objects {A, B} give two non-self directed comparisons: A→B uses g(A)−g(B), B→A uses g(B)−g(A); same magnitudes, flipped signs.

I/O Summary

discordance(diff, p, v) Input: already-oriented diff: ndarray(B1,B2,C); p, v: ndarray(C) in each criterion's units.
Output: d_j: ndarray(B1,B2,C). Each entry measures opposition to the assertion a → b, not a probability.
Preconditions: finite values, exact criterion-axis lengths, 0 ≤ p ≤ v. These are caller responsibilities, not validated here.
Piecewise formula (p < v) dj(a,b) = 0 if diff ≥ −pj;
dj(a,b) = 1 if diff ≤ −vj;
otherwise dj(a,b) = (−diff − pj) / (vj − pj).
At p=v, the veto-first branch wins at equality: diff=−p=−v gives 1.
Pipeline boundary ranking.compute_ranking negates minimize criteria before forming differences. Direct callers must orient data once.
This function neither weights criteria nor computes credibility. credibility() combines d with C(a,b); full veto sets S(a,b)=0 in this implementation.
Range
dj ∈ [0,1] for finite valid inputs
Direction
larger diff means less opposition
Boundary
p=v: equality gives 1, not 0
Weights
not used by discordance()
Scientific grounding, calibration and sanity checks

Definition: Discordance measures how strongly one criterion opposes the claim that object a is at least as good as object b. It is not 1 minus concordance: q/p describe support, while p/v describe opposition. Between −v and −p, partial concordance is already zero while discordance increases.

Calibration: p is a meaningful preference gap; v is a gap large enough to veto the claim. Elicit these from domain judgments and measurement uncertainty. They are distances in the same units as the corresponding criterion, not learned automatically by this function. If a scale changes, transform its thresholds consistently. Check 0 ≤ q ≤ p ≤ v upstream.

Sanity checks: Inspect diff near −p and −v, then test p=v separately. Increase a's performance with b fixed: opposition must not increase. Reverse objects and recompute; do not assume symmetry. Check missing data before calling; clipping does not repair NaN.

Validation ownership: CriterionConfig checks finite thresholds at construction. The ranking entry point validates the performance matrix. The low-level discordance function assumes valid inputs; NumPy broadcasting can conceal a length-one vector mismatch. Mutating a configuration after construction can bypass constructor checks.

Purpose

This module computes per-criterion opposition, not an overall ranking. In ELECTRE III credibility, strong opposition can block an assertion supported by other criteria. This repository then uses net-flow ranking, not ELECTRE III distillation.

I/O

The module imports NumPy and exports discordance(diff, p, v). Every pair of objects has one result per criterion; there is no weighting or summation in this module.

Why

Concordance collects support from a coalition of criteria. Discordance retains individual objections instead of averaging them away. A low-weight criterion can therefore trigger a full veto in the later credibility stage.

Pitfalls

Do not interpret d as a probability or as 1 minus concordance. An assertion a → b is being assessed, not declared true. See notation and the worked example.

Purpose

The function maps each oriented performance difference to a measure of opposition. A negative diff means a is worse than b on that criterion.

I/O

diff has shape (B1,B2,C); p and v must each have shape (C,). NumPy aligns these threshold vectors with the last axis. The result has the same shape as diff for these valid shapes and does not modify the input arrays.

Why

Broadcasting applies criterion k’s thresholds to every object pair, without allocating a separate threshold tensor. Row and column object groups can have different sizes; criteria remain the shared final axis.

Pitfalls

The signature does not check dimensions or lengths. A length-one threshold can silently broadcast to all criteria; other mismatches can raise ValueError. Check finite values and exact shapes upstream. The docstring lists the usual p<v branches; for p=v, use the actual veto-first precedence in R4.

R3 Interpolation L27–L30 pure
discordance.pyL27–L30
27    # Compute full interpolated values first for correct broadcasting
28    denom = v - p
29    denom = np.where(denom == 0, 1.0, denom)
30    d_interp = (-diff - p) / denom

Purpose

For p<v and −v<diff<−p, compute d = (−diff − p)/(v − p). The numerator is the disadvantage beyond p; the denominator is the width of the transition interval.

I/O

denom is a (C,) vector; d_interp broadcasts to (B1,B2,C). Intermediate values can fall outside [0,1] because interpolation is computed for every element before the piecewise branches select the final values.

Why

At diff=−p the numerator is zero; at diff=−v it equals v−p. This gives the desired endpoints. The interior slope with respect to diff is −1/(v−p): narrower intervals make opposition more sensitive to small changes.

Pitfalls

When p=v, the denominator guard substitutes 1 to avoid division by zero. This does not approximate the interval: the later branches mask interpolation completely. Invalid v<p cannot be repaired by clipping. Large blocks also allocate intermediate arrays, so memory cost scales with B1×B2×C.

R4 Piecewise Conditions L32–L34 pure
discordance.pyL32–L34
32    # Apply conditions: veto checked first, then no-discordance, then interpolate
33    d = np.where(diff <= -v, 1.0, np.where(diff >= -p, 0.0, d_interp))
34    return np.clip(d, 0.0, 1.0)

Purpose

Apply the veto branch first: diff ≤ −v gives d=1. Otherwise diff ≥ −p gives d=0. All remaining elements use interpolation. The final clip bounds valid finite results to [0,1].

I/O

The outer np.where defines priority. With p=v, both inequalities hold at equality; the outer branch returns 1. Below the shared threshold d=1; above it d=0. This is a discontinuous binary veto.

Why

Branch order expresses a model convention, not just an implementation detail. Reversing the branches would change d at p=v equality. Concordance instead gives c=1 at q=p equality because its support branch is outermost.

Pitfalls

Do not describe p=v equality as no opposition. NaN survives comparisons and clipping; positive and negative infinity may saturate to 0 and 1. Those finite-looking results do not validate the inputs. Threshold-edge and non-finite tests must distinguish these cases.

Purpose

Connect d to credibility without assigning that responsibility to this function. In this implementation any d≥1 sets S(a,b)=0, including when C(a,b)=1. For 0≤d<1, only criteria with d>C(a,b) reduce S.

I/O

credibility() receives C_ab with shape (B1,B2) and d_j with shape (B1,B2,C). It starts from C_ab and applies factors (1−d)/(1−C) where C<d<1. Discordance returns only d_j.

Why

No opposition (d=0) does not mean full support (c=1). A partial objection below C causes no reduction. A full veto is a separate rule and must not be replaced by a vague “may reduce” statement. The sensitivity example separates these outcomes.

Pitfalls

Diagonal clearing belongs to compute_block for corresponding self-comparisons, not discordance(). When p=v=0, even diff=0 gives d=1 before any diagonal clearing. Verify this convention against your application. Performance depends on block size, criterion count and hardware; no universal timing or speedup is claimed.

Run the sensitivity example

Illustrative inputs only. Do not treat these thresholds as recommended defaults. This code computes the table above, rather than printing a prewritten result.

Python — same A, B and three scenarios as above
import numpy as np
from electre3.concordance import (
    partial_concordance, global_concordance,
)
from electre3.discordance import discordance
from electre3.credibility import credibility

A = np.array([10., 5., 7.])
B = np.array([8., 7., 6.])
q = np.array([1., 1., 1.])
p = np.array([3., 3., 3.])
v = np.array([6., 6., 6.])
weights = np.array([0.5, 0.3, 0.2])
results = []
for second_value in (7., 10.5, 11.):
    scenario_B = B.copy()
    scenario_B[1] = second_value
    diff = (A - scenario_B)[None, None, :]
    c = partial_concordance(diff, q, p)
    C_ab = global_concordance(c, weights)
    d = discordance(diff, p, v)
    S = credibility(C_ab, d)
    results.append((second_value, d.copy(), C_ab, S))
    print(second_value, d, C_ab, S)

Interpretation

Each scenario still compares two objects. Only B's second measured performance changes. The criterion count and all thresholds and weights remain fixed.

For the reverse direction, swap A and scenario_B when forming diff. Do not negate the returned discordance scores.
