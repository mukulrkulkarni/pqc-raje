Block computation

compute_block(G_rows, G_cols, q, p, v, weights, is_diagonal) → ndarray

Integrates Modules: concordance, discordance, credibility
Flow: diff → c_j → C_ab → d_j → S
Output

Diagonal
when is_diagonal=True, zeros first min(B1,B2) diagonal elements
Preconditions
G_rows(B1,C), G_cols(B2,C) with matching C; not enforced here
Mismatch
C must match; otherwise NumPy may error or silently mis-compute
Scientific grounding & calibration notes

Blockwise computation: For large N, storing the full N×N credibility matrix is infeasible. compute_block processes B1×B2 submatrices at a time, enabling O(B²) memory per iteration instead of O(N²) total.

Diagonal clearing: When is_diagonal=True, np.fill_diagonal zeros the first min(B1,B2) diagonal elements. Full self-comparison diagonal (all S(a,a)=0) only occurs when the block is square and G_rows/G_cols correspond to the same alternatives. For non-diagonal blocks, all S(a,b) values are meaningful comparisons.

Module integration: This function orchestrates the ELECTRE III pipeline for one block: compute pairwise differences, pass through concordance, discordance, and credibility modules. Each module is tested independently; this function composes them.

Sanity checks:

  • Verify output shape matches (B1, B2).
  • Verify all S values are in [0,1] (clipped by credibility module).
  • For diagonal blocks, verify S[i,i] == 0 for all i.
  • Verify threshold arrays q/p/v/weights have length C matching matrix columns.

Purpose

I/O

  • G_rows[:, np.newaxis, :] — shape (B1, 1, C)
  • G_cols[np.newaxis, :, :] — shape (1, B2, C)
  • diff — shape (B1, B2, C)

Why

[Placeholder] Vectorized broadcasting computes all B1×B2×C differences in one operation, avoiding nested loops.

Pitfalls

[Placeholder] If G_rows and G_cols have different column counts, broadcasting may fail or produce incorrect shapes.

Why

[Placeholder] Credibility module handles the veto effect formula. Output is clipped to [0,1] assuming finite inputs.

[Placeholder] If d_j contains values outside [0,1], credibility may produce unexpected results. Validated upstream.

R5 Diagonal Handling L46–L50 edge

Purpose

[Placeholder] When is_diagonal=True, zeros the first min(B1,B2) diagonal elements. Full S(a,a)=0 only if block is square and rows/cols are same alternatives.

I/O

  • is_diagonal — True when G_rows and G_cols reference the same alternatives
  • S — modified in place; first min(B1,B2) diagonal elements set to 0.0

Why

[Placeholder] Self-comparison is undefined in ELECTRE III. Zeroing diagonal ensures accumulator does not count self-dominance in net flow calculation.

Pitfalls

[Placeholder] np.fill_diagonal zeros min(B1,B2) elements regardless of shape. Caller should only set is_diagonal=True for square blocks where rows/cols are same alternatives.

Usage example

example.pysnippet
from electre3.block import compute_block
import numpy as np

# Example: 3 alternatives, 2 criteria
G = np.array([[100, 8], [120, 7], [90, 9]])
q = np.array([5, 1])
p = np.array([10, 3])
v = np.array([20, 5])
w = np.array([0.4, 0.6])

# Full matrix as single block (diagonal)
S = compute_block(G, G, q, p, v, w, is_diagonal=True)
print(f"S shape: {S.shape}")
print(f"S diagonal: {np.diag(S)}")
