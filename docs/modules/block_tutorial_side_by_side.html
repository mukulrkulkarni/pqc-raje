Scientific grounding & calibration notes

Blockwise computation: For large N, storing the full N×N credibility matrix is infeasible. compute_block processes B1×B2 submatrices at a time, enabling O(B²) memory per iteration instead of O(N²) total.

Diagonal clearing: When is_diagonal=True, np.fill_diagonal zeros the first min(B1,B2) diagonal elements. Full self-comparison diagonal (all S(a,a)=0) only occurs when the block is square and G_rows/G_cols correspond to the same alternatives. For non-diagonal blocks, all S(a,b) values are meaningful comparisons.

Module integration: This function orchestrates the ELECTRE III pipeline for one block: compute pairwise differences, pass through concordance, discordance, and credibility modules. Each module is tested independently; this function composes them.

Sanity checks:

  • Verify output shape matches (B1, B2).
  • Verify all S values are in [0,1] (clipped by credibility module).
  • For diagonal blocks, verify S[i,i] == 0 for all i.
  • Verify threshold arrays q/p/v/weights have length C matching matrix columns.

Purpose

Computes one B1×B2 block of the credibility matrix S(a,b). It composes concordance, discordance, and credibility for that block.

I/O

  • G_rows — performance matrix rows for alternatives a (shape B1×C)
  • G_cols — performance matrix rows for alternatives b (shape B2×C)
  • q, p, v — threshold arrays (length C)
  • weights — normalized criterion weights (length C)
  • is_diagonal — True if same alternatives in rows and cols

Why

This single call is what the ranking loop repeats blockwise. It keeps the ranking pipeline small and avoids exposing intermediate arrays.

Pitfalls

compute_block does not validate shapes. Callers must ensure column count C matches q/p/v/weights length. Set is_diagonal=True only for diagonal blocks where rows and cols reference the same alternatives (so self-comparisons exist).

R2 Diff Computation L33–L34 core
block.pyL33–L34
33    # Compute differences: diff[i,j,k] = G_rows[i,k] - G_cols[j,k]
34    diff = G_rows[:, np.newaxis, :] - G_cols[np.newaxis, :, :]

Purpose

Computes pairwise differences for all (a,b) pairs across all criteria. By definition diff[i,j,k] = g_k(a_i) - g_k(b_j), so positive values mean the row alternative performs better on criterion k (after any minimise-column negation done upstream).

I/O

  • G_rows[:, np.newaxis, :] — shape (B1, 1, C)
  • G_cols[np.newaxis, :, :] — shape (1, B2, C)
  • diff — shape (B1, B2, C)

Why

Broadcasting computes all B1×B2×C differences in one vectorised operation. This is the main O(B1·B2·C) working array.

Pitfalls

If G_rows and G_cols do not share the same C, broadcasting fails (or yields an incorrect shape if a dimension is 1). Validate upstream.

41    d_j = discordance(diff, p, v)

Purpose

Runs the two comparisons: concordance (support) and discordance (veto pressure). It produces c_j, C_ab, and d_j for this block.

I/O

  • c_j — shape (B1, B2, C), values in [0,1]
  • C_ab — shape (B1, B2), global concordance in [0,1]
  • d_j — shape (B1, B2, C), discordance in [0,1]

Why

Keeping concordance/discordance in separate modules enables focused unit tests. compute_block is the composition point tested end-to-end.

Pitfalls

Ensure structural constraints hold: 0 ≤ q ≤ p ≤ v and w.sum() ≈ 1 (use np.isclose). Equality is allowed and has defined boundary behavior: at q=p, concordance returns 1 at diff=-q; at p=v, discordance returns 1 at diff=-v. In this codebase, high-level entry points validate shapes and basic consistency; note: validate.py enforces ordering of q/p/v but does not check q/p/v finiteness if you bypass CriterionConfig; compute_block assumes inputs are consistent.

R4 Credibility L43–L44 aggregation
block.pyL43–L44
43    # Credibility
44    S = credibility(C_ab, d_j)

Purpose

Combines global concordance C_ab and per-criterion discordance d_j into final credibility S(a,b). Only criteria with d_j > C_ab attenuate credibility (veto pressure).

I/O

  • C_ab — global concordance (B1, B2)
  • d_j — discordance per criterion (B1, B2, C)
  • S — credibility matrix (B1, B2), values in [0,1]

Why

The credibility module implements the ELECTRE III veto aggregation. It clips the final S into [0,1] for finite numeric inputs. This is not input validation: NaN remains NaN; direct callers must validate.

Pitfalls

If inputs are inconsistent (wrong shapes, NaN/Inf, non-normalised weights), downstream modules can return NaN or misleading values. High-level entry points validate; compute_block does not.

R5 Diagonal Handling L46–L50 edge
block.pyL46–L50
46    # Diagonal: S(a,a) = 0
47    if is_diagonal:
48        np.fill_diagonal(S, 0.0)
49
50    return S

Purpose

When is_diagonal=True, NumPy clears the first min(B1,B2) diagonal entries of S. In the ranking pipeline, is_diagonal is only true for diagonal blocks (same alternative group in rows and cols), so these entries correspond to self-comparisons S(a,a).

I/O

  • is_diagonal — True when G_rows and G_cols reference the same alternatives
  • S — modified in place; first min(B1,B2) diagonal elements set to 0.0

Why

Self-comparison is undefined, so the project uses the convention S(a,a)=0. In net-flow ranking, diagonal entries cancel in outflow(a) - inflow(a), but clearing them keeps the matrix convention explicit and keeps the separate components (outflow and inflow) free of self-terms.

Pitfalls

np.fill_diagonal always zeros min(B1,B2) entries, even for rectangular blocks. The ranking pipeline only sets is_diagonal=True when the block is truly diagonal (same alternatives in rows and cols), so self-terms exist at matching local indices.

Usage example

example.pysnippet
from electre3.block import compute_block
import numpy as np

# Example: 3 alternatives, 2 criteria
G = np.array([[100, 8], [120, 7], [90, 9]])
q = np.array([5, 1])
p = np.array([10, 3])
v = np.array([20, 5])
w = np.array([0.4, 0.6])

# Full matrix as single block (diagonal)
S = compute_block(G, G, q, p, v, w, is_diagonal=True)
print(f"S shape: {S.shape}")
print(f"S diagonal: {np.diag(S)}")
