Tutorial

Configuration Module

This module defines the input specification for ELECTRE III analysis. It provides typed dataclasses that capture criterion parameters and compute settings. All downstream modules consume these configurations.

Pipeline Context

The ELECTRE III engine processes alternatives through this pipeline:

  1. config (this module) — Define criteria and thresholds
  2. concordance — Compute pairwise agreement indices
  3. discordance — Compute pairwise veto indices
  4. credibility — Combine concordance and discordance
  5. block — Process large matrices in O(N) memory blocks
  6. ranking — Produce final ordering via net flow

Configuration objects flow through the entire pipeline. Basic validation (threshold ordering, positive weights) occurs at construction via __post_init__. Additional validation may be performed by validate.py; callers should validate inputs before computation.

Design Principle: Fail fast. Threshold violations raise ValueError at object creation, not at matrix processing time.

Walkthrough

R1 CriterionConfig Fields

Each criterion requires six parameters:

  • name: str — Identifier for logging and output labels
  • weight: float — Relative importance (normalized by normalize_weights)
  • q: float — Indifference threshold. Differences below q are negligible.
  • p: float — Preference threshold. Differences at or above p show clear preference.
  • v: float — Veto threshold. Differences at or above v can override concordance.
  • maximize: bool — Direction. True means higher values are better.

R2 Threshold Validation

The __post_init__ method enforces the mathematical constraint:

0 ≤ q ≤ p ≤ v

This ordering reflects ELECTRE III semantics: indifference must be narrower than preference, which must be narrower than veto. The constraint prevents mathematically invalid configurations from entering the pipeline.

R3 ComputeConfig Fields

Controls engine execution:

  • block_size: int = 1000 — Number of alternatives per block. Controls memory vs. overhead tradeoff. Larger blocks reduce function-call overhead but increase peak memory.
  • use_numba: bool = True — Enable JIT compilation. Set False if Numba is unavailable or for debugging.
  • seed: Optional[int] = None — Random seed for deterministic tie-breaking. Set to an integer for reproducible results.

R4 Block Size Validation

The engine requires at least one alternative per block. A block_size of zero or negative would cause division errors in the blocking logic.

R5 Weight Normalization

ELECTRE III requires weights that sum to 1.0. This function transforms arbitrary positive weights into normalized form. The transformation preserves relative importance ratios.

Key Constraints

  1. Threshold ordering: 0 ≤ q ≤ p ≤ v for each criterion
  2. Positive weights: Each weight > 0; sum normalized to 1.0
  3. Determinism: Set seed for reproducible rankings across runs
  4. Block size: block_size ≥ 1; typical values 500–2000

Usage Example

from electre3.config import CriterionConfig, ComputeConfig, normalize_weights

criteria = [
    CriterionConfig("Price", weight=3, q=5, p=10, v=20, maximize=False),
    CriterionConfig("Quality", weight=2, q=2, p=5, v=10, maximize=True),
    CriterionConfig("Delivery", weight=1, q=1, p=3, v=7, maximize=False),
]

weights = normalize_weights(criteria)  # [0.5, 0.333, 0.167]

config = ComputeConfig(block_size=500, seed=42)
