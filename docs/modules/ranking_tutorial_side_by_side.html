Notation — read this first

a and b are objects Both are alternatives: things being ranked (IP addresses, items, projects). They are not criteria. A criterion is a property we measure on every object.
a → b is an assertion under assessment a → b reads “a is at least as good as b”. We are testing this claim, not stating it is already established. b → a is a different claim with its own numbers.
Counts (no symbol collisions)
  • N — number of objects in the whole dataset
  • C — number of criteria (a count only)
  • C(a,b) — global concordance of the pair; in [0,1] under the weight contract below; never plain C
B1 and B2 count objects in comparison groups One block compares a group of B1 row objects (playing a) against a group of B2 column objects (playing b). Both groups contain object rows from the same performance matrix, not groups of data fields. Row/column names describe their positions in the pairwise result. Groups may overlap, and B1 need not equal B2.
Why diff has three axes (B1, B2, C) diff[i,j,k] = g(row i, crit k) − g(col j, crit k). Here g(a,j) is the oriented performance of object a on criterion j. Axis 1 picks the row object, axis 2 the column object, axis 3 the criterion. Every a,b pair gets one number per criterion.
Triple brackets [[[d1, d2, d3]]] = B1 = 1 (outer), B2 = 1 (middle), C = 3 (inner). Two objects {A, B} give two non-self directed comparisons: A→B uses g(A)−g(B), B→A uses g(B)−g(A); same magnitudes, flipped signs.

I/O Summary

compute_ranking(G, criteria, config=None) Inputs: finite numeric G: ndarray(N,C), N ≥ 2; non-empty list of C CriterionConfig objects; ComputeConfig with positive integer block_size B.
Output: (order, acc). order is a permutation of zero-based row indices, shape (N,), NOT object IDs or scores. acc is a NetFlowAccumulator.
Use a signed floating-point matrix for safe minimization: negating unsigned values can wrap. The function copies G but preserves its dtype.
Raw net flow drives ordering out(a)=Σb≠aS(a,b); in(a)=Σb≠aS(b,a).
φ(a)=out(a)−in(a). The return uses np.argsort(-acc.net_flow()): largest raw flow first.
Tie order is not explicitly stabilized or resolved by object ID. A position in order is not a confidence measure.
Normalization terminology phi_norm is a planning term, not a variable computed by ranking.py. This function does not call normalize().
Optional acc.normalize() uses min–max scaling: (φ−min φ)/(max φ−min φ); all equal maps to 0.5.
Dividing raw flow by N−1 is a different convention, not this method. Neither changes strict order within one dataset in exact arithmetic; near ties can be affected by floating-point rounding.

Scientific grounding, scaling and sanity checks

Definition: Ranking exploits ELECTRE III credibility using a net-flow score. This is not ELECTRE III distillation. A sorted list does not make the underlying directed outranking relation transitive, nor prove that each higher-ranked object outranks every lower-ranked object.

Block dimensions: B is the configured maximum number of objects per block side. B1 and B2 are actual row/column group sizes; the final groups can be smaller. The two loops visit every ordered block, including both directions, so they do not assume symmetry.

Memory and performance: The accumulator arrays use O(N), but G_adj copies O(NC) data and block differences/intermediates use O(B1×B2×C). Blocking avoids retaining the full N×N credibility matrix; it does not remove quadratic pairwise work. Measure on your hardware/data; no runtime or speedup is guaranteed here.

Current configuration behavior: ranking.py reads block_size; it does not read seed or use_numba. These fields do not select tie-breaking or an accelerated backend in this function. Do not infer backend behavior from configuration names alone.

Normalization: Min–max scores are relative to the current set and sensitive to extreme scores. A value of 1 means the largest flow in this set, not perfect credibility or probability. Constant-score 0.5 is a display convention. Dividing by N−1 instead puts finite valid net flow within [−1,1]; it is not the implementation's normalize() method.

Validation ownership: The entry point rejects empty criteria, malformed/non-finite performance matrices and non-finite weights, and checks threshold ordering. Constructors check finite thresholds and positive weights/block sizes. Public dataclasses remain mutable; post-construction mutation can bypass some checks. Overflow from extreme finite values is not comprehensively guarded. This is not a promise that every bad dtype or configuration receives a friendly ValueError.

Sanity checks: order must be a permutation of input row indices; flow at those indices must be non-increasing. Test B=1, a non-divisor of N, and B>N. Flow sums approximately to zero for consistently accumulated blocks, but this alone cannot prove diagonal exclusion: a diagonal contribution cancels between inflow and outflow.

Worked example: two objects, four blocks, one ordering

Direction: A → B has 0.85 support; the reverse direction has 0.75. Both are needed. The difference in outgoing/incoming support gives the flow.

Purpose

compute_ranking connects validated performances to pairwise credibility and then to a net-flow ordering. It accepts object rows and criterion configurations; it does not accept an NxN pairwise matrix or a comparator callback.

I/O

The function returns order and an accumulator. order contains zero-based positions into G. The accumulator keeps outflow and inflow arrays indexed by original row positions, not positions in the sorted order.

Why

Keeping the accumulator supports diagnostics and optional score display without storing all pairwise results. The scalar exploitation produces a usable ordering even when the credibility relation is not transitive.

Pitfalls

Keep external object IDs alongside G and index them with order. Never treat an order array as scores. The type annotations do not enforce numeric dtype; prefer a signed floating-point matrix for reliable orientation and arithmetic.

Purpose

Reject empty criteria, choose a default configuration if needed, validate threshold ordering, normalize weights and validate the matrix. Then assemble threshold vectors with one entry per criterion.

I/O

G must be two-dimensional with at least two rows and exactly len(criteria) columns; NaN/Inf performance values are rejected. Weights are normalized separately; q, p and v become float64 arrays before length matching.

Why

A consistent final criterion axis is essential for broadcasting in the block helper. Normalized positive weights give the global concordance weighted-average interpretation. Constructor checks enforce initial finite thresholds, their ordering and positive weights.

Pitfalls

Do not generalize these checks into complete runtime type validation. Configurations can be mutated after construction; validate_thresholds does not repeat every constructor check. normalize_weights rejects non-finite values and nonpositive total, not every possible mutated negative component. Treat configuration objects as immutable in use.

R3 Orientation L23–L26 veto
ranking.pyL23–L26
23    G_adj = G.copy()
24    for j, c in enumerate(criteria):
25        if not c.maximize:
26            G_adj[:, j] = -G_adj[:, j]

Purpose

Copy G and negate each column whose criterion has maximize=False. After this step, larger oriented values mean better performance for every criterion. Differences can then use one sign convention.

I/O

G_adj has the same shape and dtype as G. Original input values are preserved. Thresholds remain nonnegative distances in each criterion’s units; they are not negated with the performances.

Why

A lower cost becomes a larger negative-cost value, reversing preference consistently without changing distance magnitudes. This orientation happens once before blocking rather than separately inside every pair computation.

Pitfalls

Do not pre-negate a column and also mark it minimize, because that reverses orientation twice. Unsigned or extreme integer values can wrap/overflow under negation. Use signed floating-point values and check practical scale ranges; finite input checks alone do not prove every later subtraction is safe.

R4 Blocks & flows L27–L32 pure
ranking.pyL27–L32
27    N, B = G.shape[0], config.block_size
28    acc = NetFlowAccumulator(N)
29    for rs in range(0, N, B):
30        for cs in range(0, N, B):
31            S = compute_block(G_adj[rs:min(rs+B,N)], G_adj[cs:min(cs+B,N)], q, p, v, weights, rs==cs)
32            acc.update(S, rs, cs)

Purpose

Visit every row block and every column block using steps of B. Each helper result is accumulated immediately: row sums add outgoing support, column sums add incoming support. The next block can replace the temporary matrix.

I/O

B1=min(B,N-rs), B2=min(B,N-cs). Each S has shape (B1,B2). update(S,rs,cs) writes sums to the matching index slices. With K=ceil(N/B), K² blocks are processed, including both off-diagonal directions.

Why

The identical partition on both axes makes rs==cs identify corresponding self-comparison blocks. compute_block clears their local diagonal before update. Other blocks must not clear their local diagonal: those positions represent different objects.

Pitfalls

Equal local row/column positions do not always mean the same object. A test of net-flow sum alone misses self-comparison leakage because diagonal terms cancel. Test block diagonals and accumulated outflow/inflow directly. O(N) describes accumulator storage only, not the entire pipeline.

R5 Order & scaling L33–L33 edge
ranking.pyL33–L33
33    return np.argsort(-acc.net_flow()), acc

Purpose

Sort negative raw flow with np.argsort to place the largest flow first. The returned accumulator remains available for inspecting each object’s incoming and outgoing support or requesting optional normalized display values.

I/O

Raw flow is outflow minus inflow, with no division by N−1 here. acc.normalize() is a separate min–max operation; all equal values map to 0.5. The planning name phi_norm is not a symbol computed or returned by ranking.py.

Why

For one fixed dataset, strictly increasing scaling preserves strict order in exact arithmetic, so raw-flow sorting need not first compute display scores. Min–max values remain relative to the current set and do not measure confidence.

Pitfalls

No explicit stable sort, object-ID secondary key or tie policy is supplied. Equal scores may appear in any order consistent with NumPy’s chosen sort; do not assert a particular tied permutation across versions. Changing block size can change floating-point summation order near ties. seed and use_numba are not read by this function.

Run the two-object ranking example

Illustrative inputs only. Do not treat these values as recommended defaults. The example computes the displayed flows and ordering.

Python — same objects and thresholds as the earlier pages
import numpy as np
from electre3.config import CriterionConfig, ComputeConfig
from electre3.ranking import compute_ranking

ids = np.array(["A", "B"])
G = np.array([[10., 5., 7.], [8., 7., 6.]])
weights = [0.5, 0.3, 0.2]
criteria = [
    CriterionConfig(f"criterion {j+1}", w, 1., 3., 6.)
    for j, w in enumerate(weights)
]
order, acc = compute_ranking(
    G, criteria, ComputeConfig(block_size=1)
)
raw_flow = acc.net_flow()
display_score = acc.normalize()  # optional, separate call
ranked_ids = ids[order]
print(ranked_ids, raw_flow, display_score)
print(acc.outflow, acc.inflow, acc.blocks_done)

Read the result

Map indices back to IDs using ids[order]. Scores in raw_flow and display_score still follow the original G row order; use raw_flow[order] for sorted scores.

Four blocks are processed here. They do not imply four objects: there are two objects and four ordered pairs including self-comparisons, whose credibility entries are cleared.
