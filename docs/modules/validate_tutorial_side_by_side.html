Scientific grounding & calibration notes

Fail-fast philosophy: Validation functions catch malformed inputs before they propagate through the pipeline. Catching errors early produces clear messages at the source rather than cryptic failures downstream.

Threshold semantics: The q/p/v thresholds define indifference (q), preference (p), and veto (v) zones. Their meaning and calibration are documented in the concordance/discordance modules; validate.py only enforces structural constraints (q ≥ 0, p ≥ q, v ≥ p).

Sanity checks:

  • NaN/Inf rejection: Floating-point anomalies silently corrupt downstream calculations; explicit rejection surfaces data quality issues.
  • Minimum alternatives: N ≥ 2 required because pairwise comparison needs at least two alternatives.
  • Weight normalization: Ensures relative importance is preserved while sum = 1 simplifies concordance formula.

Debugging hints:

  • ValueError: Matrix must be 2D — check that input is not a 1D array or scalar.
  • ValueError: Need at least 2 alternatives — input matrix has fewer than 2 rows.
  • ValueError: Matrix has X columns, expected Y — criteria list length does not match matrix columns.
  • ValueError: Array length mismatch — threshold arrays q/p/v/w have inconsistent lengths.

16def normalize_weights(criteria: list["CriterionConfig"]) -> np.ndarray:
17    weights = np.array([c.weight for c in criteria], dtype=np.float64)
18    if np.isnan(weights).any():
19        raise ValueError("Weights contain NaN values")
20    if np.isinf(weights).any():
21        raise ValueError("Weights contain infinite values")
22    total = weights.sum()
23    if total <= 0:
24        raise ValueError(f"Total weight must be > 0, got {total}")
25    return weights / total

Purpose

[Placeholder] Extracts weights from criteria, validates finiteness, and normalizes to sum = 1. Preserves relative ratios.

I/O

  • criteria — list of CriterionConfig with weight attribute
  • Returns ndarray of normalized weights (sum = 1.0)

Why

[Placeholder] Concordance formula assumes weights sum to 1. Normalization allows users to specify relative weights without manual scaling.

Pitfalls

[Placeholder] Zero or negative total weight is rejected. Individual negative weights are allowed if total is positive (unusual but valid for some use cases).

Usage example

example.pysnippet
from electre3.validate import (
    validate_matrix, normalize_weights, validate_arrays_match
)
from electre3.config import CriterionConfig
import numpy as np

# Example criteria
criteria = [
    CriterionConfig(name="cost", q=5, p=10, v=20, weight=2),
    CriterionConfig(name="quality", q=1, p=3, v=5, weight=3),
]

# Example matrix
G = np.array([[100, 8], [120, 7], [90, 9]])

# Validate
validate_matrix(G, len(criteria))
weights = normalize_weights(criteria)
print(f"Normalized weights: {weights}")
print(f"Sum: {weights.sum()}")
